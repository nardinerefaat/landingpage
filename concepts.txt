1.1 useState (local component state)
-----------------------------------
Academic definition:
  `useState` is React’s primitive for storing *component-local state* across renders.
  When you call its setter, React schedules a re-render, and the component is re-run
  with the new state value.

Two important forms:
  A) Direct initial value: useState(false), useState("phone"), useState({})
  B) Lazy initializer: useState(() => expensiveOrIOReadOnce())
     The function runs only on first mount (good for localStorage reads).

Where YOU used it:
  - `src/App.js`
    - `loading` (boolean gate for “Loading Products...” screen)
    - `darkMode` (boolean theme switch)
  - `src/components/home.jsx`
    - `index` for carousel slide index
  - `src/components/features.jsx`
    - `desc` toggles which item’s description is expanded
    - `showAll` toggles “See All Products” vs slice(0, 5)
    - `productAmount` object map: productId -> chosen quantity before adding
    - `query` for search input
  - `src/components/productcategory.jsx`
    - `category` tab selection
    - `desc` description toggle
    - `productAmount` quantity map
  - `src/components/navbar.jsx` and `src/components/navbarCart.jsx`
    - `open` for mobile menu drawer
  - `src/context/DataContext.js`
    - `cart` is global app-state, but stored with useState inside Context Provider
      (so any consumer can read it via useContext)

Why the “functional update” form matters:
  You used patterns like `setDarkMode(prev => !prev)` and `setCart(prev => ...)`.
  This is academically important because it prevents stale-state bugs when multiple
  updates are queued; the update receives the latest committed state.


1.2 useEffect (side effects after rendering)
--------------------------------------------
Academic definition:
  `useEffect` schedules a function to run *after* React commits the render to the DOM.
  It is used for side effects: DOM mutation, timers, network requests, subscriptions,
  and external storage (like localStorage).

Dependency array rule (core exam concept):
  - No array: runs after every render
  - []: runs once on mount (plus cleanup on unmount)
  - [x, y]: re-runs when x or y changes (by reference/value)

Where YOU used it:
  - `src/App.js` theme effect:
      useEffect(() => {
        document.documentElement.setAttribute("data-theme", darkMode ? "dark" : "light");
      }, [darkMode]);
    Meaning: the DOM attribute is a side effect; it updates whenever darkMode changes.

  - `src/App.js` bootstrap fetching effect:
      // eslint-disable-next-line
      useEffect(() => { ... loadData() }, []);
    Meaning: you intentionally run the fetch logic once on mount. You also implemented
    a “cache skip” rule: if ALL datasets already exist (length > 0), you skip refetch.

  - `src/hooks/useLocalStorage.js` persistence effect:
      useEffect(() => { localStorage.setItem(key, JSON.stringify(value)) }, [key, value])
    Meaning: synchronizes React state to localStorage whenever the state changes.

  - `src/context/DataContext.js` cart persistence effect:
      useEffect(() => { localStorage.setItem("cart", JSON.stringify(cart)) }, [cart])
    Meaning: persists cart lines on every cart update.

  - `src/components/home.jsx` timer effect (carousel):
      useEffect(() => {
        const timer = setInterval(...)
        return () => clearInterval(timer)
      }, [headset.length])
    Meaning: effect sets a timer subscription, cleanup prevents memory leaks.


1.3 useMemo (memoization / caching computed values)
---------------------------------------------------
Academic definition:
  `useMemo(fn, deps)` memoizes the *return value* of `fn` and recomputes it only when
  dependencies change. It is a performance and stability tool, not a correctness tool.

Where YOU used it:
  - `src/context/DataContext.js`
      const allProducts = useMemo(() => [...arrays].map(normalize), [value]);
    Purpose:
      - Merge multiple product sources into one list
      - Normalize product shape (especially image fields)

  - `src/components/features.jsx`
      const filteredProducts = useMemo(() => { ...filter by query... }, [datasets, query]);
    Purpose:
      - Avoid filtering again when unrelated renders happen
      - Treat filtering as a pure computation dependent on input arrays + search query

  - `src/pages/cart.jsx`
      const recommendations = useMemo(() => ..., [cart, allProducts]);
      const totalPrice = useMemo(() => cart.reduce(...), [cart]);
    Purpose:
      - Compute totals and recommendation lists only when inputs change

Academic caveat:
  useMemo compares dependencies by reference. In `DataContext`, dependency is `[value]`.
  In `src/App.js` you pass `value={{ ... }}` inline, so that object is a new reference
  on each App render. That means the memo may recompute more often than expected.
  (This is fine in small apps; it’s a scaling/performance concept.)

2.1 What a custom hook is (academic)
-----------------------------------
A custom hook is a regular JS function whose name starts with `use` and calls other
hooks. It allows you to reuse stateful logic across components without classes.

2.2 Your hook: `src/hooks/useLocalStorage.js`
---------------------------------------------
Contract:
  useLocalStorage(key, initialValue) -> [value, setValue]

How it works (two-phase design):
  Phase A — Initialization (lazy state initializer):
    - read localStorage synchronously once
    - if key exists: JSON.parse(saved)
    - else: use initialValue

  Phase B — Persistence (effect):
    - whenever `value` changes, JSON.stringify(value) and write to localStorage

Why it is correct for your catalogs:
  Catalog arrays are “cacheable” and can be restored on refresh so the app can skip
  refetching. Your App.js uses it for five keys:
    products, mobileData, audioData, tabletData, storageData

Why cart is NOT using the hook (your design choice):
  Cart is managed inside DataContext.js (because it is global app state). You still
  persist it to localStorage, but you did it manually in DataContext. This is common
  in learning projects to keep “cart logic” in one file.

Academic concept name:

3.3 Immutable updates (why you map/filter instead of editing arrays)
-------------------------------------------------------------------
React state should be treated as immutable: you create new arrays/objects instead
of mutating existing ones, so React can detect changes reliably.

Where you used immutable patterns:
  - In `addToCart`:
      prev.find(...) then prev.map(...) OR return [...prev, product]
  - In `handleQuantity`:
      delete -> prev.filter(...)
      plus/minus -> prev.map(...)
  - In `productAmount` updates:
      setProductAmount(prev => ({ ...prev, [id]: newValue }))

Academic benefit:
  Predictability, easier debugging, and compatibility with memoization and renders.


3.4 Derivations with reduce (computed state vs stored state)
------------------------------------------------------------
Stored state: `cart` array
Derived state:
  - cartItemsCount = cart.reduce((count, item) => count + (item.quantity || 0), 0)
  - totalPrice = cart.reduce((acc, item) => acc + (price * qty), 0) inside `useMemo`

Academic term:
  “Derived values” — don’t store what you can compute from source-of-truth state.

3.6 Recommendation system (rule-based scoring)
----------------------------------------------
File: `src/context/DataContext.js`
Call site: `src/pages/cart.jsx`

Signature you implemented:

Pipeline (academic form):
  1) Candidate generation (filtering)

     - require an image
     - remove items already in cart
     - dedupe by id (seen set)

  2) Feature extraction + scoring

Important behavioral rule in YOUR UI:
  In `src/pages/cart.jsx` you anchor recommendations to the FIRST cart line:

Academic naming:
  This is a heuristic recommender (content-based scoring). It is deterministic given inputs.

5) Quick glossary (for flashcards)
══════════════════════════════════════════════════════════════════════════════

Hook:
  A function that lets you “hook into” React state/lifecycle from function components.

Side effect:
  Any interaction with something outside React’s render computation (DOM, network, timers, storage).

Memoization:
  Storing the result of a computation so it can be reused when inputs are unchanged.

Normalization:
  Converting multiple data shapes into one consistent internal shape.

Immutability:
  Updating by creating new objects/arrays instead of mutating existing ones.

Derived value:
  A value computed from state rather than stored as separate state.

Heuristic recommender:
  A rule-based scoring system (not ML) that ranks candidates by simple features.
